=== DEMO 3 - Isolation: no dirty read of an uncommitted grade ===
Lecturer A starts a draft change to Ada's CSC101 CA. Lecturer B reads the same score.
committed score before demo: 26.0 (grade_id=1)
connection A (uncommitted): score=3.0 status=Draft
connection B (concurrent read): score=26.0 status=Published
PASS: B did not see A's uncommitted write (no dirty read).
after A ROLLBACK, B reads score=26.0 status=Published
SQLite default isolation (WAL): readers see the last committed snapshot, not the writer's private page.

=== DEMO 4 - Lost update (read-modify-write) and the control that prevents it ===
start score=20.0 (reset to 20)
naive RMW: A read 20.0, B read 20.0, both wrote +1, stored score=21.0
Issue: two increments were intended (22) but one increment was lost.
reset to 20; retry with atomic UPDATE and a write lock
B blocked/failed while A held the write lock: database is locked
after locked atomic increments: score=22.0 (expected 22)
Control: BEGIN IMMEDIATE + UPDATE score = score + 1. Isolation + atomic increment, no lost update.
