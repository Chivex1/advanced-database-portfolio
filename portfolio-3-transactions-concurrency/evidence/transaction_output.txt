=== DEMO 3 - Isolation: no dirty read of an uncommitted grade ===
Lecturer A starts a draft change to Ada's CSC101 CA. Lecturer B reads the same score.
committed score before demo: 26.00 (grade_id=1)
connection A (uncommitted): score=3.00 status=Draft
connection B (concurrent read): score=26.00 status=Published
PASS: B did not see A's uncommitted write (no dirty read).
after A ROLLBACK, B reads score=26.00 status=Published
InnoDB default isolation is REPEATABLE READ: readers see the last committed snapshot, not the writer's uncommitted row.

=== DEMO 4 - Lost update (read-modify-write) and the control that prevents it ===
start score=20.00 (reset to 20)
naive RMW: A read 20.00, B read 20.00, both wrote +1, stored score=21.00
Issue: two increments were intended (22) but one increment was lost.
reset to 20; retry with row lock and atomic increment
B blocked/failed while A held the write lock: (1205, 'Lock wait timeout exceeded; try restarting transaction')
after locked atomic increments: score=22.00 (expected 22)
Control: START TRANSACTION + SELECT ... FOR UPDATE + UPDATE score = score + 1.
